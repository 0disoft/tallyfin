## Enforcing Synchronous Delay Limits in Admin Requests (2026-10-12)

`ApiClient` had delegated the deadline only to a `setTimeout` callback, so if `getBearer` synchronously blocked the event loop, the callback ran late and a PATCH could still be sent after the deadline. The request now captures its end time with the `performance.now()` monotonic clock when it starts and checks the deadline immediately after credentials, immediately before dispatch, when headers arrive, and when JSON success or error handling completes. A caller abort is not masked as a timeout, already observed 401 and 403 errors remain permission errors, and the analytics-access cancellation notice is passed through. Shared login refresh is not cancelled, and saves are not retried automatically.

Before the fix, 4 new regression tests for credentials, headers, success body, and error body and 1 native HTTP mutation test failed, including a runner group failure for 6 failures in total. After the fix, the request-lifecycle, client, settings-editor, and analytics-access Node tests in `apps/admin/src/api/` passed 71/71. `typecheck:admin`, `build:admin`, bundle separation 2/2, and Sites Worker 9/9 (11/11 in total) also passed. In the native Node HTTP check, an async `getBearer` with a synchronous `Atomics.wait` of 150ms inside a `requestTimeoutMs` of 100ms produced 0 fetch dispatches and 0 PATCHes (1 prior GET), while the draft review was retained. After the block was released, checkLatest→keepChanges→save completed the GET and PATCH.

## Server SDK Credential Deadline Checks (2026-10-12)

If `getToken` took a long time synchronously, it blocked the event loop, and HTTP transmission could start between the late runs of the `requestTimeoutMs` and `retryBudgetMs` timers. Immediately before transmission, the SDK now checks `host.monotonicNow` against the attempt deadline `min(total retry deadline, attempt start + requestTimeoutMs)` and ends the attempt without an HTTP request if the deadline has passed.

The 3 new regressions (source, minified, and native HTTP) all failed before the fix and passed after it. `npm run test:server` passed 34/34, including the 3 new credential deadlines. `npm run build:server` succeeded, including declaration `tsc`; the build was 9021 bytes, gzip 3703 bytes, with 0 runtime dependencies. Sending the same event again immediately produced delivered, attempts 1, and HTTP 1, with the same `eventId`. The synchronous function itself cannot be interrupted midway, and the attempt signal is cancelled during cleanup.

The scope was SDK source unit tests, the build, and a local HTTP experiment; remote OIDC, production DB, and Worker verification were not performed.
