## 2026-10-09 schema list and new-version publication API

`GET /v1/projects/{projectId}/schemas` returns the highest version and newest-first metadata to readers/owners. It uses limit 25/maximum 100 and an exclusive beforeVersion cursor and checks the grant on every page. Owner-only `PUT /v1/projects/{projectId}/schemas/{schemaVersion}` accepts expectedLatestVersion, privacyReviewed=true, events, and workflows and publishes a new active version. It preserves the project, existing definitions, aggregates, and ingest usage and increments only ingest_revision by 1. Also verified that actual events can be stored with the new version definition.

The conditional owner/highest-version INSERT and revision update run in one atomic D1 batch. Concurrent publication of different versions succeeds only once; other requests receive schema_conflict 409. Repeating the same canonical content for the same version returns 200 with existing metadata and adds no storage or revision increment. If a later version exists or that version is retired, the repeated request returns existing state and does not reactivate it. Permission revoked immediately before storage returns 403; revision overflow rolls back through the insert and returns 503. The body limit is 33KiB and the definition itself is limited to 32KiB.
