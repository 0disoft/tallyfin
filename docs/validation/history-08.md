## Collector completion observation logs — 2026-10-11

We added `apps/collector/src/request-observation.ts`, optional `observe` and `monotonicNow` ports to `handler.ts`, and a completion-observation port, instead of error-only logging, to the native Worker in `index.ts`. At the point where a response is ready, it projects only seven fixed fields (`event`, `requestId`, `operation`, `status`, `code`, `latencyBucket`, and `samplingDenominator`). Success (code `ok`, 200/204) is sampled at 4/256 based on the first two characters of the UUID with `samplingDenominator=64`, while every failure receives a denominator of 1. It uses `console.error` for 5xx, `console.warn` for 4xx, and `console.log` otherwise. The latency bucket runs from handler start to preparation of the response object and excludes `waitUntil` background work and network transmission. If the clock is non-finite or negative, no timestamp is used; if the end is earlier than the start, it is `unknown`; and a failed observation callback or clock call does not change the response. Request bodies, URLs, paths, query parameters, methods, headers, project IDs, and target identifiers are not logged, and no separate DB write, network call, or dependency was added.

Execution and results: the first run of the five-file scope including the observation test ran 36 tests, with 35 passing and 1 failing. The failure was one native Worker log check: `DROP TABLE
projects` in the synthetic D1 was blocked by a foreign-key constraint and ended before reaching the defect guard. After changing the test fixture to `DROP TABLE project_schemas`, the focused check
`node --test --test-timeout=30000 apps/collector/test/request-observation.test.ts` passed 6/6.

--noEmit` and `tsc -p apps/collector/tsconfig.runtime.json` had exit code 0, and `git diff --check` passed. The native log check called `createWorker` directly and intercepted console output over an actual local Miniflare D1, and the collector/runtime checks run on actual workerd.

The focused tests check that all 256 UUID prefixes produce 4 success samples, all 8 failure variants, and only the approved field projection; that clock-boundary buckets and NaN, Infinity, negative, backward, and exception clocks become `unknown`; that success and preflight produce exactly one observation per response without consuming or changing the body; that a rejection response's `requestId` and `code` match the body and the callback, clock, and background work do not change the response; that admin, server, and unknown paths use only fixed `operation` values; and that the native Worker leaves no SQL errors or request data and emits exactly one line per response. The observation callback is synchronous, and asynchronous observation that returns a promise is unsupported.
